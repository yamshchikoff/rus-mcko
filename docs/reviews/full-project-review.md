## 2. Критические замечания

### 2.1. `estimate_tokens` не обрабатывает list-typed content (CRITICAL)

**Файл:** `src/tutor/compaction.py:21-23`

```python
def estimate_tokens(messages: list[dict]) -> int:
    total_chars = sum(len(m.get("content", "")) for m in messages)
    return int(total_chars / 3.5)
```

После tool-use раундов сообщения содержат `content` как **список** (например `[{"type": "tool_use", ...}]` или `[{"type": "tool_result", "content": "...длинный текст..."}]`). Для списка `len(content)` возвращает количество элементов (1–2), а не количество символов. Оценка токенов для tool-use-heavy диалогов **драматически занижается** — сжатие может не сработать, и контекстное окно будет превышено.

**Исправление:** добавить обработку list-typed content:

```python
def estimate_tokens(messages: list[dict]) -> int:
    total_chars = 0
    for m in messages:
        content = m.get("content", "")
        if isinstance(content, list):
            for block in content:
                total_chars += len(json.dumps(block, ensure_ascii=False))
        else:
            total_chars += len(content)
    return int(total_chars / 3.5)
```

### 2.2. Path traversal в раздаче `/data/` (SECURITY)

**Файл:** `src/tutor/server.py:293-304`

```python
if path.startswith("/data/"):
    rel = path[len("/data/"):]  # ← удаляет префикс
    full = PROJECT_ROOT / rel   # ← /data/../src/tutor/server.py → PROJECT_ROOT/src/tutor/server.py
```

Проверка `str(full).startswith(PROJECT_ROOT)` пропускает `/data/../src/tutor/server.py` — весь исходный код доступен для чтения. Это локальный сервер, но path traversal позволяет читать любые файлы проекта.

**Исправление:** резолвить реальный путь перед проверкой:

```python
full = (PROJECT_ROOT / rel).resolve()
if not str(full).startswith(str(PROJECT_ROOT.resolve()) + os.sep):
    self.send_error(404)
    return
```

### 2.3. localStorage quota не обрабатывается (DATA LOSS)

**Файл:** `src/frontend/legacy/index.html` — вызовы `localStorage.setItem(...)` без try/catch

`saveChatHistory`, `saveReviews`, `saveProgress`, `saveAnswer` — ни один не ловит `QuotaExceededError`. История чата (100 сообщений × многокилобайтные AI-ответы) + ревью 15 вариантов с длинными текстами анализа легко превышают лимит 5 МБ. При исчерпании квоты приложение **молча перестаёт сохранять данные** — ученик теряет прогресс и ответы.

**Исправление:** обернуть все `setItem` в try/catch, при ошибке показывать предупреждение.

### 2.4. Двойной клик по «Завершить работу» — гонка (DATA CORRUPTION)

**Файл:** `src/frontend/legacy/index.html:921-927`

`finishWork` не имеет guard'а от повторного вызова. Два быстрых клика запускают два параллельных `requestAIReview` с двумя `AbortController`. Оба сохраняют ревью и перезаписывают прогресс — порядок финализации непредсказуем.

**Исправление:** добавить флаг `isReviewInProgress`, проверять в `finishWork` и `tick`.

## 3. Серьёзные замечания

### 3.1. `notifyModelOfReview`: уведомление не доходит до модели

**Файл:** `src/frontend/legacy/index.html:274-328`

Уведомление `chatMessages.push(notification)` происходит **после** fetch (строка 312). Модель отвечает на запрос без этого сообщения — она видит прогресс через `buildTutorContext()`, но не видит уведомления «ученик только что завершил вариант». Для следующего сообщения уведомление уже будет в истории — модель ответит на него с задержкой в одно сообщение.

### 3.2. Отсутствие спецификаций для ключевых функций (METHODOLOGY)

**Файлы:** `docs/specs/` — только 3 документа

Отсутствуют спецификации для:
- ИИ-репетитор (системный промпт, сервер, чат, compaction)
- ИИ-проверка работ (`/api/review`)
- Прогресс ученика (`src/progress/`)
- Фронтенд (таймер, сохранение, модальные окна)

Методология CLAUDE.md требует: «требования фиксируются в документе спецификации». Это системный методологический долг.

### 3.3. Сжатие контекста: greedy tail-only eviction

**Файл:** `src/tutor/compaction.py:54-60`

Алгоритм проходит от конца и останавливается на первом сообщении, которое не влезает. Никогда не возвращается к ранним сообщениям. Может оставить неиспользованный бюджет токенов, который мог бы вместить ещё пару сообщений из середины истории.

### 3.4. `system_prompt.py` и `review.py` — дублирование этики

Два независимых системных промпта с пересекающимися этическими гайдлайнами. При изменении этики (например, требование заказчика) нужно править оба — неизбежно разойдутся.

### 3.5. `finishWork` использует нативный `confirm()` (UX INCONSISTENCY)

**Файл:** `src/frontend/legacy/index.html:923`

Каждое другое подтверждение в приложении — стилизованное модальное окно. Кнопка «Завершить работу» — единственное место с нативным `confirm()`. Выглядит чужеродно, особенно для школьников.

## 4. Замечания средней тяжести

### 4.1. `_handle_chat`: `Content-Length` не проверяется

**Файл:** `src/tutor/server.py:196,237`

```python
length = int(self.headers.get("Content-Length", 0))
raw = self.rfile.read(length)
```

Если заголовок отсутствует — читается 0 байт, `json.loads("")` падает с невнятной ошибкой. Если злонамеренно завышен — `rfile.read()` блокируется.

### 4.2. `broad except Exception` в `execute_tools`

**Файл:** `src/tutor/common.py:90`

```python
except Exception as exc:
    content = f"[Ошибка] {exc}"
```

Ловит `KeyboardInterrupt` и `SystemExit`, мешая чистой остановке сервера. Должно быть `except (ValueError, KeyError, TypeError)`.

### 4.3. `MIN_CONTENT_CHARS` — мёртвая константа

**Файл:** `src/textbook/constants.py:19`

`MIN_CONTENT_CHARS = 100` определена, но не используется ни в одном production-файле — только в тестах. Либо должна проверяться в `_page_extractor.py`/`build.py`, либо удалена.

### 4.4. `parse_review_response`: жадный regex для поиска JSON

**Файл:** `src/tutor/review.py:145`

```python
brace_match = re.search(r"\{[\s\S]*\}", text)
```

Жадный `*` матчит от первого `{` до последнего `}`. Если модель выводит несколько JSON-блоков — спарсится гигантская строка, которая не пройдёт `json.loads`. Фолбэк на code fence закрывает большинство случаев, но не все.

### 4.5. `simpleMarkdown` — невалидный HTML

**Файл:** `src/frontend/legacy/index.html:494`

Оборачивает весь вывод в `<p>...</p>`, но блоковые элементы (pre, ul) не могут быть внутри `<p>`. Браузер авто-закрывает `<p>` перед ними — DOM валиден, но разметка непредсказуема.

### 4.6. Frontend: нет responsive-дизайна

**Файл:** `src/frontend/legacy/sdamgia.css`

Фиксированная сетка `1fr 6px 1fr`, нет media queries. На экранах < 900px панели становятся неюзабельны. Школьники часто заходят с планшетов.

### 4.7. `CLAUDE.md` устарел

Ключ `vpr-chat-{номер варианта}` документирован, но коммит `6803a1e` заменил его на единый `vpr-chat`. Спецификация `vpr-integration.md` имеет статус «ожидание URL сайта-источника» — URL давно получен, данные извлечены.

## 5. Лёгкие замечания

### 5.1. `printed_page` convention не документирована

`build.py` и `_toc_parser.py` оба полагаются на `printed_page = pdf_page - 1`, но ни один не документирует это. Связка держится на совпадении.

### 5.2. `_extract_trailing_page`: хардкод 1–200

**Файл:** `src/textbook/_toc_parser.py:151`

Лимит страниц 1–200 вшит. Для данного учебника (185+149=334 стр.) работает, но для любого другого — молча обрежет номера страниц >200.

### 5.3. `toggleById`: неявный глобальный `event`

**Файл:** `src/frontend/legacy/index.html:783`

Использует `window.event` (legacy API). Работает, но нестандартно.

### 5.4. Chat: нет ARIA-атрибутов

Нет `aria-live`, `role="log"` — скринридеры не анонсируют новые сообщения.

### 5.5. Модальные окна: нет accessibility

Нет `role="dialog"`, `aria-modal="true"`, focus trapping. Фокус не перемещается в модальное окно при открытии.

### 5.6. Цветовой контраст `--muted`

#888 на белом фоне = ~3.0:1. WCAG AA требует 4.5:1.

### 5.7. Resize handle: только мышь

Нет `tabindex`, `role="separator"`, keyboard handlers. Разделитель панелей недоступен с клавиатуры.

### 5.8. `saveAnswer`: утечка таймеров при быстрых кликах

Несколько кликов за 1.5с ставят несколько `setTimeout` — все меняют кнопку обратно на «Ответить». Визуальный flicker.

### 5.9. `apiKey` modal: Cancel не работает на первом запуске

`hideApiKeyModal` делает `if (!hasApiKey()) return` — на первом запуске ключа нет, Cancel игнорируется, модальное окно не закрывается.
