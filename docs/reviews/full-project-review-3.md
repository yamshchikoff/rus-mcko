## 1. Критические (4)

### K3.1. XSS в ссылках на учебник — `ref.part` и `ref.page` не экранированы

**Файл:** `src/frontend/legacy/index.html:434`

```javascript
html += `<span class="review-textbook-ref">${escHtml(ref.paragraph || '')} (ч. ${ref.part || '?'}, стр. ${ref.page || '?'})</span>`;
```

`escHtml()` применяется только к `ref.paragraph`. Поля `ref.part` и `ref.page` приходят с сервера (результат работы LLM) и вставляются в `innerHTML` без экранирования. Если модель вернёт `page: "<img src=x onerror=alert(1)>"`, это XSS.

**Исправление:** `escHtml(ref.part || '?')` и `escHtml(ref.page || '?')`.

---

### K3.2. `parseScores` возвращает второй наименьший балл, а не максимальный

**Файл:** `src/frontend/legacy/index.html:902-918`

```javascript
const sorted = [...new Set(raw)].sort((a, b) => a - b);
const min = sorted[0] ?? 0;
const next = sorted.length > 1 ? sorted[1] : min + 1;  // всегда sorted[1], не sorted[-1]
```

Для критериев с баллами [0, 1, 2, 3] функция возвращает `next = 1` (второй наименьший), а не `3` (максимальный). `scoreTask()` (строка 929) возвращает `next` для любого непустого ответа — т.е. максимум 1 балл вместо потенциальных 2–3.

Это задокументировано как «стаб-заглушка до прикрутки ИИ-проверки», но стаб должен возвращать хотя бы максимальный балл для непустого ответа. Сейчас он систематически занижает результаты.

**Исправление:** `const max = sorted[sorted.length - 1]; const next = sorted.length > 1 ? max : min + 1;`

---

### K3.3. `renderProgressTable` хардкодит 15 вариантов вместо `variants.length`

**Файл:** `src/frontend/legacy/index.html:1001`

```javascript
for (let vNum = 1; vNum <= 15; vNum++) {  // хардкод 15
```

При этом `exportProgress` (строка 1022) корректно использует `variants.length || 15`. Если данных станет 12 или 18 вариантов, таблица прогресса либо покажет пустые строки, либо молча пропустит варианты.

**Исправление:** `for (let vNum = 1; vNum <= (variants.length || 15); vNum++)`

---

### K3.4. `toggleById` полагается на устаревший `window.event`

**Файл:** `src/frontend/legacy/index.html:805`

```javascript
function toggleById(id) {
  const btn = event.target;  // window.event — deprecated, нестандартно
```

Работает в большинстве браузеров, но нестандартно и не работает в строгом режиме. Все вызовы `toggleById` идут из inline `onclick`. Параметр `event` не передаётся.

**Исправление:** передавать `event` вторым параметром: `toggleById(id, event)`, или перейти на `addEventListener`.

## 2. Серьёзные (5)

### С3.1. Дублирование tool-use цикла: `server.py` и `review.py`

**Файлы:** `src/tutor/server.py:87-145`, `src/tutor/review.py:174-244`

Два почти идентичных цикла: построение запроса, заголовки, вызов API, проверка `stop_reason`, извлечение текста, обработка tool_use. ~50 строк дублирования. Изменение в одном цикле (например, новый stop_reason) должно быть вручную повторено в другом.

**Рекомендация:** вынести `run_tool_use_loop` в `common.py` как общую функцию, параметризуемую системным промптом и сообщениями.

---

### С3.2. Дублирование форматирования TOC: `common.py` и `tools.py`

**Файлы:** `src/tutor/common.py:53-70` (`_fmt_entry`), `src/textbook/tools.py:34-46` (`_format_entry`)

Две почти идентичные рекурсивные функции форматирования оглавления. Отличаются только именами параметров и одним `if`-условием. Изменение формата вывода TOC требует правок в двух местах.

**Рекомендация:** `common.py` должен импортировать `_format_entry` из `tools.py`, либо обе должны делегировать к общей функции в `tools.py`.

---

### С3.3. Отсутствие теста на критический фикс `estimate_tokens`

**Файлы:** `src/tutor/compaction.py:22-34`, `tests/tutor/test_compaction.py`

В первом ревью был найден критический баг: `estimate_tokens` не обрабатывал list-типизированный `content` (tool_use/tool_result блоки), что могло привести к переполнению контекстного окна. Баг исправлен (`isinstance(content, list)` + `json.dumps`), но **ни одного теста на этот случай не добавлено**.

Если кто-то отрефакторит `estimate_tokens` и уберёт list-обработку — ни один тест не упадёт. Это регрессионный риск для самой критичной функции сжатия контекста.

**Рекомендация:** добавить тест `test_handles_list_typed_content` с сообщением, содержащим `content: [{type: "text", text: "..."}, ...]`.

---

### С3.4. Связность `_page_index`: три модуля зависят от недокументированного ключа

**Файлы:** `src/tutor/server.py:46`, `src/tutor/common.py:83`, `src/textbook/tools.py:15-16`

`_page_index` (словарь `{(part, pdf_page): page_dict}`) строится в трёх разных местах:
- `server.py:46` — внутри `load_textbook()`
- `tools.py:15-16` — внутри `_load()`
- `common.py:83` — потребляет `textbook["_page_index"].get((part, page))`

Если textbook загружен минуя `load_textbook()` или `_load()`, индекс отсутствует и `common.execute_tools` падает с `KeyError`. Этот контракт не документирован и не протестирован.

**Рекомендация:** индексация при загрузке JSON (при build или при первом чтении) как часть структуры данных, а не как runtime-сайд-эффект.

---

### С3.5. `/api/chat` fetch без таймаута

**Файл:** `src/frontend/legacy/index.html:600-612`

`/api/review` имеет 6-минутный таймаут (`AbortController` + `setTimeout`). `/api/chat` — нет. Если серверный прокси зависнет (например, DeepSeek API не отвечает), запрос чата никогда не завершится, кнопка отправки останется заблокированной навсегда.

**Рекомендация:** добавить `AbortController` с таймаутом 120 секунд для чат-запросов.
