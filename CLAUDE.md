# rus-mcko

Сервис тренировочных контрольных работ по русскому языку в формате ВПР для 7 класса (2026 год).

## Контекст

Основная масса семиклассников уже написала свои работы ВПР. Часть детей работу провалила — теперь им предстоит переписывание. Наш сервис — тренажёр, который поможет им подготовиться к переписыванию: набить руку на типовых заданиях, разобрать ошибки и прийти на пересдачу увереннее.

## Назначение

Дать провалившим ВПР школьникам инструмент для подготовки к переписыванию работы.

## Основные возможности

- Прохождение тренировочных работ в формате ВПР за 7 класс
- Автоматическая проверка ответов
- Просмотр результатов и разбор ошибок
- Повторные попытки для закрепления материала
- ИИ-репетитор по русскому языку: чат с моделью, опирающейся на учебник

## Методология разработки

**TDD** (Test-Driven Development) — единственный принятый подход. Любая функциональность проходит через цикл RED → GREEN → REFACTOR.

### Жизненный цикл фазы разработки

1. **Обсуждение** — устное или текстовое обсуждение задачи, выявление требований и границ. Каждая фиксация результатов обсуждения оформляется отдельным коммитом. Мы стремимся к атомарным коммитам обсуждений: один коммит — одна зафиксированная мысль или решение.
2. **Спецификация** — требования фиксируются в документе спецификации и сохраняются в директории `docs/specs/`.
3. **Планирование (Plan Mode)** — **жёсткое требование**: любая фактическая работа над кодом выполняется строго через plan mode. План фазы должен явно содержать три субфазы:
   - **RED** — написание тестов, которые падают (фиксация ожидаемого поведения).
   - **GREEN** — минимальная реализация, проходящая тесты.
   - **REFACTOR** — рефакторинг реализации до полного соответствия назначению, без изменения поведения.
4. **Коммит после каждой субфазы** — после RED, GREEN и REFACTOR делается отдельный коммит и push во все ремоуты.
   - **Каждое изменение кода — отдельный коммит.** Не накапливать несколько правок в рабочем дереве. Одна законченная правка = один коммит + push.
   - **Коммит и push — безопасные операции.** Не спрашивать разрешения перед коммитом или пушем — коммитами ничего нельзя испортить.
5. **Ревью** — после завершения всех субфаз фазы проводится обязательное ревью. Результат ревью фиксируется в отчёте ревьюера (`docs/reviews/`).

### Подпись коммитов

Все коммиты подписываются соавтором `deepseek-v4-pro <noreply@deepseek.com>`, так как базовая модель агентского ИИ в этом проекте — deepseek-v4-pro (несмотря на использование харнесса Claude Code).

Формат:
```
Co-Authored-By: deepseek-v4-pro <noreply@deepseek.com>
```

## Данные ВПР

15 реальных вариантов ВПР по русскому языку для 7 класса (2025-2026), извлечены с [`rus7-vpr.sdamgia.ru`](https://rus7-vpr.sdamgia.ru/). Каждый вариант — 7 заданий (К1–К7): осложнённое списывание, понимание текста, многозначные слова, морфологический разбор, правописание предлогов и союзов, пунктуация.

- **Данные:** `data/vpr/variants.json` (meta, constructor, 15 variants × 7 tasks с формулировками, решениями и критериями)
- **Скрипт извлечения:** `src/vpr/extract.py` (переизвлечение при обновлении вариантов на источнике)
- **Урезанный фронтенд:** `src/frontend/legacy/index.html` (статический, выбор варианта, поля ввода, раскрытие ответов)
- **Тесты:** `tests/vpr/test_extract.py` (15 тестов на структуру данных)

### Интерактивные возможности фронтенда

**Таймер (45 минут, привязан к варианту):**
- Запускается при выборе варианта, новый таймер — при каждой смене варианта
- Sticky-бар: отображает прошедшее и оставшееся время
- Кнопка «Пауза» / «Продолжить» — приостанавливает и возобновляет отсчёт
- Кнопка «Заново» — открывает модальное окно с подтверждением «Начать всю работу сначала?»
  - **Да** — сбрасывает таймер, очищает все сохранённые ответы текущего варианта, таймер стартует с 0
  - **Нет** — закрывает окно, таймер продолжается в том же состоянии (идёт или на паузе)
- При истечении 45 минут — всплывает предупреждение «Время вышло»

**Смена варианта:**
- При выборе другого варианта (когда текущий уже активен) — модальное окно «Сбросить прогресс по текущей работе и сменить вариант?»
  - **Да** — очищает ответы текущего варианта из localStorage, загружает новый вариант с новым таймером
  - **Нет** — закрывает окно, селектор возвращается к текущему варианту, таймер продолжается
- Выбор того же варианта игнорируется
- Первый выбор варианта (когда ни один не активен) — модальное окно не показывается

**Сохранение ответов:**
- Кнопка «Ответить» у каждого задания сохраняет содержимое поля ввода в `localStorage`
- Ключ: `vpr-ans-{номер варианта}-{номер задания}` (7 ключей на вариант)
- Обратная связь: кнопка на 1.5 сек меняется на «Сохранено ✓»
- При открытии варианта ранее сохранённые ответы автоматически восстанавливаются
- При сбросе (кнопка «Заново» → «Да») — ответы удаляются из localStorage и поля очищаются
- При смене варианта (с подтверждением «Да») — ответы предыдущего варианта удаляются

**Отслеживание прогресса:**
- Таблица 15 вариантов × 7 тем (К1–К7) + столбец «Завершён» с датой и временем
- В ячейках — балл за задание (число), для незавершённых вариантов — прочерк
- Данные хранятся в `localStorage` под ключом `vpr-progress`:
  ```json
  { "номер варианта": { "completed": "ISO-дата", "scores": { "1": балл, ..., "7": балл } } }
  ```
- Вариант считается завершённым при:
  - Нажатии кнопки «Завершить работу» (с подтверждением)
  - Истечении таймера (45 минут) — автоматически
- **Стаб-подсчёт баллов** (заглушка до прикрутки ИИ-проверки):
  - Из criteria_html каждого задания парсятся возможные баллы (последняя ячейка каждой строки таблицы критериев)
  - Пустой ответ → младший балл (обычно 0)
  - Непустой ответ → следующий за младшим балл (обычно 1)
  - `parseScores(criteriaHtml)` → `{min, next}`, `scoreTask(vNum, issue)` → число
- Кнопка «Прогресс» рядом с селектором варианта — открывает таблицу в любой момент
- При завершении таблица прогресса показывается автоматически
- Кнопка «Скрыть» в заголовке секции — скрывает таблицу

### Сохранение результатов ИИ-проверки (ревью)

- Результаты ИИ-проверки сохраняются в `localStorage` под ключом `vpr-review-{номер варианта}`
- При открытии варианта ранее полученное ревью автоматически отображается под каждым заданием
- Ревью переживает перезагрузку страницы и закрытие браузера
- При смене варианта (с подтверждением) ревью старого варианта удаляется
- Ревью включает: балл за задание, strengths, weaknesses, recommendation, ссылки на параграфы учебника
- При ошибке парсинга ответа модели (parse_error) показывается сырой текст под первым заданием

### Персистентность таймера

- Состояние таймера сохраняется в `localStorage` под ключом `vpr-timer-state` каждые 5 секунд
- При перезагрузке страницы или случайном закрытии браузера:
  - Активный вариант автоматически восстанавливается
  - Таймер продолжается с сохранённого момента (время «офлайна» не засчитывается)
  - Кнопка «Продолжить» для возобновления работы
- При завершении работы или истечении таймера состояние сбрасывается
- Таймер запускается только по кнопке «Начать работу», а не автоматически при выборе варианта

## Прогресс ученика

Данные прогресса хранятся в `localStorage` браузера и могут быть экспортированы в JSON (кнопка «Скачать» в разделе прогресса). Для преобразования в LLM-читаемый формат используется тулинг `src/progress/`.

- **Экспорт из фронтенда:** кнопка «Скачать» → `vpr-progress.json` (прогресс + ответы + дата экспорта)
- **Форматирование для LLM:** `src/progress/format.py`
  - `format_progress(progress, variants, answers)` → полный markdown-отчёт
  - `progress_as_context(progress, variants, answers)` → сжатая версия для системного промпта
- **Тесты:** `tests/progress/test_format.py` (18 тестов)
- **Формат вывода:** markdown с разделами «Сводка», «Темы заданий», «Матрица прогресса», «Детали по вариантам», «Темы требующие внимания», «Интерпретация для ИИ-репетитора»

## ИИ-репетитор

Двухколоночный интерфейс: левая половина — чат с ИИ-репетитором, правая — задания ВПР. Репетитор работает на модели `deepseek-v4-pro` через DeepSeek Anthropic-совместимый API.

### Архитектура

Тонкий Python-прокси (`src/tutor/server.py`): браузер не вызывает DeepSeek API напрямую — ключ остаётся в процессе сервера.

```
Браузер ──POST /api/chat──> server.py ──Messages API──> api.deepseek.com
  (apiKey в теле)         (учебник в памяти)       (tool-use цикл)
```

### Системный промпт (`src/tutor/system_prompt.py`)

- Модель позиционируется как репетитор по русскому языку для учеников 7 класса (13–14 лет)
- Опирается исключительно на учебник (Баранов, Ладыженская, 2022) — «Алмазный фундамент»
- Защита от провокаций: мягко возвращает разговор в учебное русло
- Инструменты: `show_toc()` — оглавление учебника, `get_page(part, page)` — текст страницы
- Поддерживает инъекцию контекста прогресса ученика и текущего задания

### Инструменты навигации по учебнику (`src/textbook/tools.py`)

- `show_toc()` — возвращает форматированное оглавление с номерами параграфов и PDF-страниц
- `get_page(part, page)` — возвращает текст конкретной страницы (part: 1 или 2)
- Учебник загружается из `data/textbook/textbook.json` (~315 страниц) в память при старте сервера
- Инструменты передаются модели в формате Anthropic Messages API (`tools`)

### Цикл tool-use (`src/tutor/server.py`)

1. Клиент отправляет сообщения в `POST /api/chat`
2. Сервер добавляет системный промпт + tools definition
3. Запрос к DeepSeek Messages API (`https://api.deepseek.com/anthropic/v1/messages`)
4. Если модель возвращает `stop_reason: "tool_use"`:
   - Сервер исполняет инструмент локально из textbook.json
   - Результат добавляется в историю сообщений
   - Запрос повторяется (до 5 итераций)
5. Финальный ответ возвращается клиенту

### Сжатие контекста (`src/tutor/compaction.py`)

- Оценка токенов: `сумма символов / 3.5`
- Порог сжатия: ~170K токенов (~600K символов)
- Стратегия MVP: системный промпт сохраняется, старые сообщения отсекаются с головы
- Выполняется перед каждым запросом к API в цикле tool-use

### Фронтенд чата

- Левая колонка (50%): заголовок «ИИ-репетитор», скроллящийся чат, поле ввода с textarea
- Правая колонка (50%): весь существующий функционал ВПР
- Разделитель колонок: 6px, перетаскивается мышкой (min 20%, max 80%)
- Enter = отправить сообщение, Ctrl+Enter = новая строка
- Кнопка отправки (↑) рядом с полем ввода
- Сообщения пользователя — правое выравнивание, синий фон
- Сообщения репетитора — левое выравнивание, бежевый фон
- Базовый Markdown-рендеринг: жирный, курсив, списки, код
- История чата: `localStorage` ключ `vpr-chat-{номер варианта}`, до 100 сообщений
- При смене варианта — загружается история для нового варианта
- Модальное окно ввода API-ключа при первом запуске (input type=password)
- Кнопка ⚙ в заголовке чата для смены ключа

### Контекст, передаваемый репетитору

При отправке сообщения фронтенд собирает и передаёт серверу:
- Текущий вариант и формулировки заданий (из `variants.json`)
- Прогресс ученика (из `vpr-progress` в localStorage)
- История диалога (из `vpr-chat-{N}`)

### Запуск

```bash
python3 src/tutor/server.py --port 8080
```

Заменил `python3 -m http.server`. Сервер раздаёт статику из `src/frontend/legacy/`, данные из `data/` и обслуживает API.
