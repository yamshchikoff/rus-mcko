# rus-mcko

Сервис тренировочных контрольных работ по русскому языку в формате ВПР для 7 класса (2026 год).

## Контекст

Основная масса семиклассников уже написала свои работы ВПР. Часть детей работу провалила — теперь им предстоит переписывание. Наш сервис — тренажёр, который поможет им подготовиться к переписыванию: набить руку на типовых заданиях, разобрать ошибки и прийти на пересдачу увереннее.

## Назначение

Дать провалившим ВПР школьникам инструмент для подготовки к переписыванию работы.

## Основные возможности

- Прохождение тренировочных работ в формате ВПР за 7 класс
- Автоматическая проверка ответов
- Просмотр результатов и разбор ошибок
- Повторные попытки для закрепления материала

LLM опирается на эти документы непосредственно в рантайме, а не через заранее извлечённые и захардкоженные правила. Документы являются авторитетным источником истины для модели.

- **Авторы:** М.Т. Баранов, Т.А. Ладыженская, Л.А. Тростенцова, Н.В. Ладыженская и др.

## Методология разработки

**TDD** (Test-Driven Development) — единственный принятый подход. Любая функциональность проходит через цикл RED → GREEN → REFACTOR.

### Жизненный цикл фазы разработки

1. **Обсуждение** — устное или текстовое обсуждение задачи, выявление требований и границ. Каждая фиксация результатов обсуждения оформляется отдельным коммитом. Мы стремимся к атомарным коммитам обсуждений: один коммит — одна зафиксированная мысль или решение.
2. **Спецификация** — требования фиксируются в документе спецификации и сохраняются в директории `docs/specs/`.
3. **Планирование (Plan Mode)** — **жёсткое требование**: любая фактическая работа над кодом выполняется строго через plan mode. План фазы должен явно содержать три субфазы:
   - **RED** — написание тестов, которые падают (фиксация ожидаемого поведения).
   - **GREEN** — минимальная реализация, проходящая тесты.
   - **REFACTOR** — рефакторинг реализации до полного соответствия назначению, без изменения поведения.
4. **Коммит после каждой субфазы** — после RED, GREEN и REFACTOR делается отдельный коммит и push во все ремоуты.
5. **Ревью** — после завершения всех субфаз фазы проводится обязательное ревью. Результат ревью фиксируется в отчёте ревьюера (`docs/reviews/`).

### Подпись коммитов

Все коммиты подписываются соавтором `deepseek-v4-pro <noreply@deepseek.com>`, так как базовая модель агентского ИИ в этом проекте — deepseek-v4-pro (несмотря на использование харнесса Claude Code).

Формат:
```
Co-Authored-By: deepseek-v4-pro <noreply@deepseek.com>
```

## Данные ВПР

15 реальных вариантов ВПР по русскому языку для 7 класса (2025-2026), извлечены с [`rus7-vpr.sdamgia.ru`](https://rus7-vpr.sdamgia.ru/). Каждый вариант — 7 заданий (К1–К7): осложнённое списывание, понимание текста, многозначные слова, морфологический разбор, правописание предлогов и союзов, пунктуация.

- **Данные:** `data/vpr/variants.json` (meta, constructor, 15 variants × 7 tasks с формулировками, решениями и критериями)
- **Скрипт извлечения:** `src/vpr/extract.py` (переизвлечение при обновлении вариантов на источнике)
- **Урезанный фронтенд:** `src/frontend/legacy/index.html` (статический, выбор варианта, поля ввода, раскрытие ответов)
- **Тесты:** `tests/vpr/test_extract.py` (15 тестов на структуру данных)

### Интерактивные возможности фронтенда

**Таймер (45 минут, привязан к варианту):**
- Запускается при выборе варианта, новый таймер — при каждой смене варианта
- Sticky-бар: отображает прошедшее и оставшееся время
- Кнопка «Пауза» / «Продолжить» — приостанавливает и возобновляет отсчёт
- Кнопка «Заново» — открывает модальное окно с подтверждением «Начать всю работу сначала?»
  - **Да** — сбрасывает таймер, очищает все сохранённые ответы текущего варианта, таймер стартует с 0
  - **Нет** — закрывает окно, таймер продолжается в том же состоянии (идёт или на паузе)
- При истечении 45 минут — всплывает предупреждение «Время вышло»

**Смена варианта:**
- При выборе другого варианта (когда текущий уже активен) — модальное окно «Сбросить прогресс по текущей работе и сменить вариант?»
  - **Да** — очищает ответы текущего варианта из localStorage, загружает новый вариант с новым таймером
  - **Нет** — закрывает окно, селектор возвращается к текущему варианту, таймер продолжается
- Выбор того же варианта игнорируется
- Первый выбор варианта (когда ни один не активен) — модальное окно не показывается

**Сохранение ответов:**
- Кнопка «Ответить» у каждого задания сохраняет содержимое поля ввода в `localStorage`
- Ключ: `vpr-ans-{номер варианта}-{номер задания}` (7 ключей на вариант)
- Обратная связь: кнопка на 1.5 сек меняется на «Сохранено ✓»
- При открытии варианта ранее сохранённые ответы автоматически восстанавливаются
- При сбросе (кнопка «Заново» → «Да») — ответы удаляются из localStorage и поля очищаются
- При смене варианта (с подтверждением «Да») — ответы предыдущего варианта удаляются

**Отслеживание прогресса:**
- Таблица 15 вариантов × 7 тем (К1–К7) + столбец «Завершён» с датой и временем
- В ячейках — балл за задание (число), для незавершённых вариантов — прочерк
- Данные хранятся в `localStorage` под ключом `vpr-progress`:
  ```json
  { "номер варианта": { "completed": "ISO-дата", "scores": { "1": балл, ..., "7": балл } } }
  ```
- Вариант считается завершённым при:
  - Нажатии кнопки «Завершить работу» (с подтверждением)
  - Истечении таймера (45 минут) — автоматически
- **Стаб-подсчёт баллов** (заглушка до прикрутки ИИ-проверки):
  - Из criteria_html каждого задания парсятся возможные баллы (последняя ячейка каждой строки таблицы критериев)
  - Пустой ответ → младший балл (обычно 0)
  - Непустой ответ → следующий за младшим балл (обычно 1)
  - `parseScores(criteriaHtml)` → `{min, next}`, `scoreTask(vNum, issue)` → число
- Кнопка «Прогресс» рядом с селектором варианта — открывает таблицу в любой момент
- При завершении таблица прогресса показывается автоматически
- Кнопка «Скрыть» в заголовке секции — скрывает таблицу
